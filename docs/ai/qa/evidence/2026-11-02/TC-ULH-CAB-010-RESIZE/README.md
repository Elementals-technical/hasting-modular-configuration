# TC-ULH-CAB-010-RESIZE: Resize ▸ Width нижнего уровня

Норма: R-ULH-CAB-010 (approved), комментарий клиента `gdoc-1QB6Rx-dev-feedback#C50` (bug evidence). K-URB-018 открыт.

Среда: Chrome через `chrome-devtools-mcp@1.12.0`, локальный dev на `http://localhost:5173`, HEAD `593b5416` + правка в рабочем дереве, viewport 1920×907, write-guard включён. База без правки: копия `git archive HEAD` на порту 5174.

Сценарий: Prebuilt ULH, модель 61″ Multi-Level, `Create Your Own`, Side Cabinet через «+» Cabinet Builder, выбор шкафа, меню `Resize ▸ Width`.

Шкафы выбирались через `getSelectTool().setSelectedByName`, «+» через `mousedown` на его DOM-кнопке, как в прошлых сценариях. Варианты меню открывались настоящим hover.

Ресайз нижнего шкафа до 47.2″ применился: низ 180 см, верх 260 см, столешница не изменилась (`03`).

## Длинный нижний уровень: верх 90 см, низ 255 см

Нижний шкаф 90 см доходит до 41.3″ (лимит 105 см), 47.2″ скрыт (`04`). Шкаф 105 см доходит до 47.2″. Верхний Sink Base 90 см показывает все свои ширины. До правки лимит для этого шкафа был бы 270 см: значение посчитано по формуле, этот состав на коде без правки не запускался.

- Firefox, staging, SKU и цена: цена в кадрах менялась, но с oracle не сверялась.

## Отдельный дефект: Undo теряет уровни

Статус TC-ULH-HISTORY-LAYOUT: FAIL. На коде без правки воспроизводится так же (`05`).

1. Добавить шкаф через «+» в Multi-Level композицию.
2. Изменить ширину нижнего шкафа через `Resize ▸ Width`.
3. Нажать Undo.

Итог: все шкафы получают `group-1`, столешница считается по всем шкафам (290 см вместо 140 см), карточки Builder выключаются.

Снимок истории после добавления хранится без `sceneLayout`: `past` содержит `layout: true` для 3 шкафов и `layout: false` для следующих. Если добавлений не было, Undo того же ресайза сохраняет уровни. Почему снимок остаётся без раскладки, не выяснено: кандидаты `readLayout` в `captureSnapshot.ts` и `captureFreeLayout`.
